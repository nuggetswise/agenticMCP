## ShipHawk, from ShipHawk's own documentation

| Fact | Source |
| --- | --- |
| ShipHawk does not integrate with EDI providers directly and does not generate ship notices; the EDI provider builds the 856 from the shipment data | ShipHawk Guide, How ShipHawk Works with EDI Providers (shiphawk.atlassian.net/wiki/spaces/HELP/pages/83001461) |
| Shipment fields offered: shipment ID, carrier, service, shipping cost, carton SSCC, pallet SSCC, package ID, tracking or PRO number | same |

| Any other provider reads the shipment by API (GET shipment) or webhook (shipment.create_from_order) | same |

| Carton and pallet labels: ShipHawk builds GS1-128 labels from templates and can take carton labels from the SPS Commerce label library | ShipHawk Guide, wiki/x/AQBAC and wiki/x/AoDqJ |
| ERP integrations must take both pallet and carton SSCC when the container is a pallet | ShipHawk ERP Integration Guide (wiki/x/CIDPKg), search extract |

Not found: any mention of OpenText or Trading Grid as a named provider.

**Journey moment:** Operate, at pack and ship. ShipHawk sits between the warehouse's packing step and the ship notice: it rates, books, labels and assigns carton and pallet SSCCs, then writes those facts to the ERP's fulfillment record, from which the EDI provider builds the 856.

**What the customer gains over Trading Grid alone:** carton and pallet SSCCs and labels produced at pack time and written to the record the ship notice is built from, so the label on the box and the ship notice agree. Trading Grid alone takes whatever carton detail the ERP holds.

**Division of labour:** ShipHawk rates, books, labels and assigns SSCCs; the ERP holds the fulfillment; Trading Grid builds and sends the 856 to Northfield.

**Stop if** (derived here, not from a brief, because ShipHawk has none): ShipHawk cannot write to the fields Trading Grid's ERP connector reads and the API route lacks the carton-to-item detail; the customer's warehouse system already produces compliant SSCC labels; ShipHawk expects to own the retailer EDI.

**Questions only ShipHawk can answer**

1. Can the SuiteApp write carton and pallet SSCC, package ID and tracking into the fields Trading Grid's NetSuite connector reads, as it does for SPS Commerce and TrueCommerce?
2. Outside NetSuite, does the shipment API or webhook carry which items sit in which carton, which an 856 needs?
3. Would ShipHawk take a retailer's carton label specification from Trading Grid, as it takes labels from SPS Commerce?
4. Which shared customers ship to retailers that require SSCC labels, and may they be named?
