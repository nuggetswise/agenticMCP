# T2.3 agent governance: stories 1, 2 and 4

Story 3 (a changed agent rule replays beside the rule in force) was done earlier (CALLS 78, gate check `governance.replay_shows_a_changed_authority`). This change builds stories 1, 2 and 4. The governance golden questions are parked (CALLS 79) and are not built here.

## Story 1: every write names agent, authority, approver and outcome

**What it does.** Each write's access-log row carries four facts:

- the agent or person who proposed it
- the authority it ran under: the rule id and a mode. The modes are `suggest`, `approve`, `policy` (standing policy), and `person`, which means a person acted directly.
- who approved it
- the outcome

The same fields go on the other company's log when the write lands in a shared record. `get_access_log` returns them as `write: { agent, authority: { rule, mode }, approver, outcome }`, and the admin page shows them in a column.

**Writes covered:**

- the proposal tools: `request_change`, `submit_dispute`, `release_ship_notice`, `decide_charge` and `publish_rule`, including refused calls. A refused call records "None: nothing was recorded".
- the AP-4.1 dispute that Claim Agent submits without asking. It is logged as Claim Agent, AP-4.1, `policy`, "Standing policy AP-4.1, set by Priya Raman".
- each decision: `approve_proposal`, `reject_proposal` and `edit_proposal`
- the `counterparty:*` rows
- `pause_agent`, `resume_agent` and `replay_agent_rule`
- every state change of a Scout session proposal (`scout:<action>`)

**Case history.** The case history shows the same facts. Approved `case.dispute`, `case.decision`, `rule.published` and `tg.release` events now carry `drafted_by` (the proposer), `authority` and `proposal`. Dispute and decision events also carry `outcome`.

**Where:**

- `log()`, `propose()`, `write()` and `decide()` in `src/server.js`
- in `src/scout.js`, `audit()` records each Scout proposal state change in `session.audit`, and `drainScout()` in `src/server.js` copies those records into the access log
- new nullable columns on `access_log` in `world/schema.sql`: `agent`, `authority_rule`, `authority_mode`, `approver` and `outcome`
- `proposals` gains `authority_mode` and `note`

Neither table is in the read-only SQL copies, so the SQL tool descriptions are unchanged.

**Checks:**

- Gate: `governance.every_scout_write_names_agent_authority_approver_outcome` covers every proposal in the baseline of all five variations: 45 entries, each with a final entry.
- Gate: `governance.standing_policy_write_names_the_policy` covers the AP-1.4 build under standing policy.
- Smoke:
  - "every write names agent, authority, approver and outcome" checks both logs after the DC-41118 case is worked from both sides.
  - "dispute write: Claim Agent under AP-4.1, Priya approves"
  - "charge decision: NF-7.7, Jordan approves, shown on Ashby's log too"
  - "case history shows authority and outcome"
  - "Scout writes on the access log with agent, authority, approver, outcome"

**Not exercised end to end.** No undisputed case in the recorded world lets Claim Agent dispute without asking: each eligible case is already disputed. The AP-4.1 automatic row's attribution is therefore not reached by smoke. Its gate, `G.mayActWithoutAsking`, is checked at the function level (story 2).

## Story 2: pause and override

**What it does.**

- **Pause and resume.** An administrator can pause any agent of their connection:
  - Ashby: Watch, Claim, Test, Shelf, Scout and Pace Agent
  - Northfield: Review and Match Agent

  The administrator can also resume a paused agent. A repeat changes nothing. An agent of the other company is refused. Each pause or resume is a change-list entry with who made it and why, plus an attributed access-log row.
- **What a paused agent does.** The server enforces the pause. The client is not trusted to.
  - `recommend_next_step` for the agent's job returns a plain task (R15): the record and the job, with `proposal: null` and no next step, decision row or authority.
  - A paused Claim Agent disputes nothing without asking. `submit_dispute` becomes a proposal by Priya Raman's assistant, with the reason "Claim Agent is paused".
  - A paused Review Agent gives no recommendation in `review_deduction_case`, and `decide_charge` carries none.
  - A paused Match Agent gives no next step in `three_way_match`.
  - A paused Scout gets no model turn. `runScout` checks the pause before the first call, before every step and after every model answer, and discards any answer that arrives after a pause. `scout_start` returns `status: paused` with a `plain_task` that holds the rule engine's findings and no proposal. `scout_decide` still records Priya's decision but does not resume Scout. `scout_replay` runs the baseline and reports Scout as blocked.
- **Override (Edit suggestion, R15).** Priya sets one proposal aside and does the case by hand. The proposal's state becomes "Taken over", and the record names her, with an optional note. Nothing is appended to the world. A proposal that has been taken over cannot then be approved.
  - Trading Grid proposals: admin route `/admin/:token/proposals/:id/edit`, logged as `edit_proposal`.
  - Scout: `scout_decide` with `decision: edit` and an optional `note`. After an override, Scout proposes nothing more in that session (`handed_to_person`). Proposals still awaiting a decision stay with Priya.

**Where:**

- `src/governance.js`: `AGENTS`, `agentState`, `isPaused`, `setAgentState`, `plainTask` and `mayActWithoutAsking`
- `src/server.js`: the pause gates in `call()` and `write()`; `decide(..., 'edit')`; `scoutPaused` and `scoutGov`
- `src/scout.js`: the `paused` option of `runScout`; `decide(..., 'edit')`
- `src/pages.js`: an Agents card with Pause and Resume buttons, and an "Edit suggestion" button on each proposal

**New tools:**

- `pause_agent` and `resume_agent` on both connections. These are writes (`readOnlyHint: false`).
- `get_change_list` on both connections (read-only)

**New routes:**

- `POST /admin/:token/agents/:agent/pause|resume`
- `POST /admin/:token/proposals/:id/edit`

  - `governance.resume_restores_and_both_are_logged`

## Story 4: the trial record

**What it does.** Each replay of a changed agent rule is recorded as a change-list entry. The entry holds:

- what changed (the rule and its parameters, before and after)
- the replay result: the records whose next step or authority differs, and the count unchanged
- the drift measure
- the rule in force and the rollback path
- who ran it, and when

Nothing is published, and the catalogue is unchanged. There are two kinds of trial:

- **Fixed agents: `replay_agent_rule`** (Ashby). This runs `replayAgentRule`. Only Ashby-owned rules can be trialled, and only parameters the catalogue already holds. Deduction cases default to every case of the quarter up to `as_of`.
- **Scout: `scout_replay`.** Every call is recorded as a trial. A new optional `policy` argument changes an editable action's mode. The baseline then also runs under the policy in force, and the actions whose authority differs are listed. Locked actions (AP-1.3 release, AP-1.4 build, AP-5.1 reserved stock) are reported as refused changes.

**Readable back.** Entries are stored in a new table, `agent_changes`. They are read with the `get_change_list` tool on either connection, filterable by kind, and on the admin page. The table is dropped from both read-only SQL copies, as `access_log`, `proposals` and `rule_replays` are. An admin reset clears it.

**Where:**

- `src/governance.js`: `trialAgentRule`, `recordTrial` and `changeList`
- `src/scout.js`: `replay(..., { policy })`, which returns `policy_trial`
- `src/server.js`: `scoutReplay`
- `world/schema.sql` and `world/build.js`

**Checks:**

- Gate:
  - `governance.trial_recorded_on_the_change_list`: AP-4.1 changed from 250 to 50 moves DC-40877 only. The check covers drift, rollback, who ran the trial and when.
  - `governance.trial_refuses_rules_it_cannot_change`
  - `governance.scout_policy_trial_shows_authority_beside_the_policy_in_force`
- Smoke:
  - "trial of a changed agent rule recorded on the change list"
  - "the trial publishes nothing"
  - "a trial of another company's rule is refused"
  - "Scout replay of a changed policy recorded as a trial"
